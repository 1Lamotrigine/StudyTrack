# StudyTrack — учебное пространство на Next.js + PGlite

Актуальные изменения интерфейса, структуры и правил: [PRODUCT_CHANGES.md](docs/PRODUCT_CHANGES.md).

Самостоятельная версия учебного портала. Django, Python, Docker и отдельный сервер PostgreSQL для работы не нужны. Node.js 22.13+ (или актуальная LTS).

```sh
cd nextjs
npm ci
npm run dev
```

Открыть http://127.0.0.1:3000. Production: `npm run build`, затем `npm start`. Другой порт: `npm start -- --port 3107`.

Развёртывание на Vercel: [инструкция и особенности хранения](docs/VERCEL.md).

При локальном запуске база автоматически создаётся при первом обращении в `data/studytrack`. Данные сохраняются после перезапуска. Путь меняется через `PGLITE_DATA_DIR` (в `.env.local` или окружении). Для HTTPS задайте `COOKIE_SECURE=true`. Не запускайте несколько процессов с одним каталогом PGlite; остановите dev перед production и перед резервным копированием.

## Возможности

- Вход, выход, серверные сессии на 12 часов, проверка актуальной роли и активности на каждом запросе.
- Личный обзор по роли, карточки курсов, фильтры и прогресс, иерархия категорий.
- Мои задания `/tasks` и очередь проверки `/review`, статусы и обратная связь.
- Черновики в текущей вкладке, ошибки рядом с формой, сохранение заполненных полей, состояния ожидания.
- Задания, версии работ, проверка зачисления, запрет повторной сдачи, отметка просрочки.
- Оценивание преподавателем своего курса, исправления и история оценок.
- Отчёты по сдаваемости, средним результатам студентов и курсам.
- Русский полнотекстовый поиск, JSONB, вычисляемые столбцы, GIN и B-tree индексы.
- Администратор: создание и изменение пользователей, роли, отключение, установка нового пароля; категории; курсы и архивирование; задания; зачисления и отчисления; аудит.

## Проверки

```sh
npm test
npm run typecheck
npm run build
# При запущенном приложении на порту 3107:
npm run test:smoke
# Другой адрес:
TEST_URL=http://127.0.0.1:3000 npm run test:smoke
```

Тест БД создаёт независимую базу в памяти, не меняет рабочие данные. HTTP smoke-тест входит тремя ролями, проверяет страницы и запрет админки студенту; создаёт только сессии. Для изолированного предпросмотра используйте отдельный каталог: `PGLITE_DATA_DIR=./data/preview npm start -- --port 3110`.

`npm run format:check` проверяет оформление кода; `npm run format` применяет форматирование.

## Резервное копирование

Остановите приложение, затем:

```sh
npm run db:backup
npm run db:restore -- backups/studytrack-TIMESTAMP.tar.gz ./data/restored
PGLITE_DATA_DIR=./data/restored npm start
```

Восстановление допускается только в новый каталог. `backup/studytrack.dump` — исходный архив PostgreSQL, сохранённый для истории; это другой формат, скрипт PGlite его не импортирует. Инициализация новой версии использует исходный демонстрационный seed, а не содержимое внешнего работающего PostgreSQL.

## Структура и совместимость

`app/` — маршруты и Server Actions; `features/` — отдельные предметные экраны; `components/` — общий UI; `lib/` — БД, авторизация и серверная валидация; `db/` — исходные DDL, данные, процедуры, индексы и последовательные миграции; `tests/` — интеграционные проверки; `scripts/` — smoke, backup и restore; `docs/` — анализ миграции и исходные учебные материалы.

В `sql/` сохранены оригинальные учебные примеры PostgreSQL. Они содержат команды psql (`\\gset`, переменные), поэтому не предназначены для прямой передачи в `PGlite.exec`. Демонстрации нескольких сеансов, deadlock, dblink, сетевых ролей и pg_dump требуют исходного PostgreSQL. `db/04_roles.reference.sql` сохранён как справочный файл и не выполняется при инициализации: права приложения проверяет сервер Next.js, предметные права дополнительно проверяют SQL-процедуры. Подробности: `docs/MIGRATION.md`.

Миграции в `db/migrations` автоматически обновляют существующую схему. Новые правила и уточнения к исходному переносу перечислены в `docs/PRODUCT_CHANGES.md`; сведения в `docs/MIGRATION.md` описывают первый этап переноса.

Сквозной тест с записью данных запускается **на отдельной базе**:

```sh
PGLITE_DATA_DIR=./data/test-flows npm start -- --port 3111
# В другом терминале:
ALLOW_TEST_WRITES=yes npm run test:flows
```

Он создаёт тестовые учётные записи и курс, проходит зачисление, сдачу, оценивание и архивирование. Обычная база приложения не используется. Скрипт backup читает `.env.local` и `.env`, как и приложение.

## SQL Workspace / DBMS

Войдите как `admin / admin123` и откройте **http://localhost:3000/dbms**. Это SQL-консоль в стиле pgAdmin 4 для той же базы приложения: редактор с подсветкой, дерево объектов, SQL и DDL, результаты, CRUD таблиц, история, EXPLAIN, ER-диаграмма и 22 учебных примера. Изменения обычного запуска сохраняются; режим «С откатом» предназначен для демонстраций. Руководство и ограничения: [docs/DBMS.md](docs/DBMS.md).
