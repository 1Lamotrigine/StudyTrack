# Развёртывание на Vercel

Выберите Framework Preset **Next.js**. Root Directory — `nextjs`, если эта папка находится внутри репозитория; если в GitHub загружено её содержимое, оставьте корень репозитория. Команда сборки: `npm run build`, установка зависимостей: `npm ci`. Output Directory оставьте стандартным.

После отправки изменений в GitHub дождитесь нового Deployment или выполните Redeploy в Vercel. Дополнительный импорт SQL и ручное создание пользователей не нужны: схема, учебные данные и три учётные записи создаются автоматически при первом обращении.

| Логин | Пароль | Роль |
|---|---|---|
| admin | admin123 | Администратор |
| teacher | teacher123 | Преподаватель |
| student | student123 | Студент |

При запуске существующей базы отсутствующие стандартные пользователи добавляются; пароли существующих пользователей не перезаписываются.

## Хранение данных

На Vercel приложение автоматически использует PGlite в памяти: каталог приложения недоступен для постоянной записи. Это демонстрационный режим. У разных серверных процессов отдельные базы; после холодного старта или нового деплоя изменения могут исчезнуть. SQL Workspace работает с базой текущего процесса. Вход стандартными аккаунтами поддерживается между процессами благодаря подписанной cookie на 12 часов.

Для общей базы с постоянным хранением на Vercel потребуется подключить внешний PostgreSQL и адаптировать слой доступа к нему. Текущая версия такой адаптер не включает. При локальном запуске PGlite по-прежнему сохраняет данные в `data/studytrack`.

Можно задать одинаковый `SESSION_SECRET` во всех окружениях одного деплоя; без него используется встроенный ключ учебной демонстрации. На Vercel cookie автоматически получает Secure. Для локальной проверки облачного режима используйте `PGLITE_DATA_DIR=memory://`.

Справка: [файлы в Vercel Functions](https://vercel.com/kb/guide/how-can-i-use-files-in-serverless-functions), [режимы хранения PGlite](https://pglite.dev/docs/).
