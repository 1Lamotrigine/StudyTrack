# StudyTrack — план выполнения по фазам

Проект по ТЗ №06 «Учёт учебных заданий и результатов» (PostgreSQL + минимальное Django-приложение).
Весь код проекта находится в каталоге `app/`. Этот файл — рабочий чек-лист: отмечаем пункт только после
реальной проверки запуском.

## Принципы

- Источник требований: `StudyTrack.pdf` (ТЗ) и `README.md` (шаблон отчёта).
- Все SQL-объекты создаются в БД; приложение не дублирует расчёты на Python.
- Пароли и реальные данные не попадают в репозиторий: только `.env.example`, данные вымышленные.
- Каждая фаза заканчивается проверяемым результатом (команда + ожидаемый вывод).
- Предзащита — после фазы 2 (схема + основной сценарий). Полная сдача — после фазы 8.

## Порядок работы

1. Фазы выполняются последовательно; после каждой — обновление чек-листа и проверка.
2. Перед изменением схемы — `docker compose down -v` (init-скрипты выполняются только при создании тома).
3. Скрипты из `sql/` запускаются вручную и не должны ломать демонстрационный набор
   (кроме явно тестовых транзакций с ROLLBACK).
4. Документация пишется по факту реализации, а не заранее.
