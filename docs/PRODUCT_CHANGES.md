# Развитие StudyTrack

## Что мешало пользоваться продуктом

1. Главная показывала общие счётчики базы вместо личных следующих действий.
2. Таблицы использовались даже для выбора курса и чтения работы. Важные действия терялись среди технических полей.
3. Студенту было сложно отличить несданное задание от отправленного и оценённого. Преподавателю не хватало общей очереди проверки.
4. При ошибке сервер перенаправлял на страницу с текстом SQL-ошибки в URL. Заполненные поля терялись, отправка не имела состояния ожидания.
5. Все пользовательские маршруты жили в одном catch-all компоненте; административные экраны и мутации были длинными условными цепочками.
6. Архивирование не закрывало сдачу. Можно было убрать последнего администратора, оставить курсы за пользователем другой роли, уменьшить максимум ниже существующих оценок.
7. В сдаваемости учитывались отчисленные студенты в числителе, но только активные — в знаменателе; средняя оценка задания повторно учитывала версии одного студента.

## Что изменено

### Интерфейс и сценарии

- Единая светлая визуальная система: фиолетовый акцент, карточки, SVG-иконки, спокойная типографика, статусные бейджи и полосы прогресса. Нет зависимости от внешних шрифтов или картинок.
- Личный обзор для трёх ролей. Студент видит свои курсы, сданные задания, ожидание проверки, результат и обратную связь. Преподаватель — свою нагрузку и очередь работ. Администратор — быстрые действия.
- Каталог курсов с вкладками «Все / Мои», поиском по названию, коду и преподавателю, фильтром активных/архивных курсов.
- `/tasks`: задания студента по состояниям «К сдаче / На проверке / Оценены / Все». Несданные работы со сроком в прошлом отмечены отдельно.
- `/review`: единая очередь проверки своих курсов, сначала ранние отправки, фильтр по курсу, предупреждение о более новой версии.
- Страница курса с заданиями и вкладкой результатов, преподавателем и прогрессом. Чужие преподаватели не получают таблицу частных работ; черновики курсов скрыты от студентов.
- Экран сдачи с условиями, деталями, историей версий и отзывами. Черновик хранится в `sessionStorage` текущей вкладки; ключ включает пользователя, задание и число отправленных версий, поэтому новый пользователь и новая пересдача не получают прежний текст. Содержимое не синхронизируется с сервером и недоступно после закрытия вкладки.
- Экран проверки с отдельной панелью оценки, диапазоном баллов, комментарием и историей. Неоценённая пересдача не стирает прежний результат отчёта.
- Поиск понимает русскую морфологию и дополнен поиском подстроки и названия курса. Техническая колонка ранга убрана.
- Аналитика ограничена своими курсами для преподавателя. Средний результат по курсу показан графически, объяснён способ расчёта.
- Административные даты вводятся нативным `datetime-local`, часовой пояс явно указан: Актобе, UTC+5. Новая запись открывается после создания.
- Формы сохраняют непарольные поля при ошибке, показывают ошибку рядом с действием и переводят на неё фокус. Отправка блокируется на время ожидания. Архивирование, отчисление и изменение доступа запрашивают подтверждение в интерфейсе.
- Добавлены пустые состояния, загрузочные скелетоны, страницы ошибки и 404, активная навигация, подписи для скринридера, переход к содержимому, `prefers-reduced-motion`, мобильная компоновка и доступный выход на телефоне.

### Структура

```text
app/
  login/                  публичный вход
  (portal)/               авторизованный layout и настоящие маршруты Next.js
    courses/              каталог и курс
    assignments/          сдача
    versions/             оценивание
    tasks/, review/       рабочие очереди
    reports/, admin/      аналитика и управление
  actions.ts              orchestration Server Actions
components/               навигация, оболочка, формы, иконки, UI-примитивы
features/
  dashboard/, courses/, submissions/, search/, reports/
  admin/                  отдельные модули пользователей, курсов, заданий и категорий
lib/
  actions/                валидация и административные операции
  auth.ts, db.ts          авторизация, соединение, миграции
  types.ts, format.ts     общие типы, русские подписи и форматирование
  page-context.ts         проверка параметров и контекст страницы
 db/migrations/           последовательные обновления существующей БД
 tests/                   проверки предметных правил и сохранности данных
```

Код отформатирован Prettier, добавлены команды `format` и `format:check`. PGlite-соединение переиспользуется при HMR; новая версия схемы применяется и к уже открытому соединению.

### Правила данных

Миграции применяются транзакционно и без повторного seed:

- Запрещена отправка работы и активное зачисление в неактивный курс. История остаётся доступна; преподаватель может проверить уже отправленные работы архивного курса.
- Нельзя отключить или понизить последнего активного администратора.
- Нельзя сменить роль студента с учебной историей или преподавателя со связанными курсами/оценками на несовместимую роль. Для другой роли нужна отдельная учётная запись.
- Смена роли, активности или пароля завершает существующие сессии пользователя.
- Нельзя переносить задание с работами в другой курс или снижать максимум ниже выставленных баллов.
- Сдаваемость считает только активных зачисленных студентов; историческое количество версий сохраняется. Средний балл задания использует последнюю оценённую версию каждого студента, а не все пересдачи.
- ID, email, логин, числовые диапазоны, дата и перечисления проверяются на сервере. Пароль проверяется как введён, без обрезки пробелов. Пароли не возвращаются в состоянии формы. Внешние адреса перехода запрещены.

## Проверки

- `npm test`: исходная схема и пароли, сдача и оценка, административные операции, ограничения, аудит, откат, поиск, персистентность, восстановление архива; новые инварианты, отозванные сессии, корректность отчётных средних и знаменателей, валидация и безопасные переходы.
- `npm run build`, `npm run typecheck`, `npm run format:check`.
- `npm run test:smoke`: 36 страниц трёх ролей, авторизация и запрет административного контента студенту. Проверка учитывает потоковые redirects Next.js, которые могут возвращать HTTP 200 с инструкцией перенаправления.
- В браузере: вход, неверный пароль и сохранение логина, выход, главные экраны студента и преподавателя, сдача, сохранение черновика после reload, мобильная ширина 390 px и настольная 1280 px.

Предпросмотр на порту 3110 использует отдельную демонстрационную базу `data/preview`, чтобы не разделять файловое хранилище с уже работающим dev-сервером. Скриншот: `docs/ui-preview.jpg`.

## Дальнейшее развитие

Файловая PGlite по-прежнему предполагает один серверный процесс на каталог данных. Для нескольких реплик потребуется внешний PostgreSQL. Уведомления, файлы-вложения, восстановление пароля по email и полноценный контроль попыток входа остаются отдельными задачами. `sessionStorage` — удобство текущей вкладки, не замена серверному хранению черновиков.

Дополнительно пройден `test:flows` через настоящие Server Actions на отдельном сервере с `data/test-flows`: создание преподавателя и студента, курса и задания, зачисление, отправка, отказ оценки выше максимума с сохранением комментария, допустимая оценка, просмотр результата студентом, отказ оценивания студентом, архивирование и отказ новой сдачи через ранее открытую форму. Тестовые данные не пишутся в рабочую базу.

## Светлая и тёмная темы

Переключатель находится в шапке портала и на странице входа; на телефоне это иконка солнца/луны рядом с выходом. Выбор сохраняется в `localStorage` браузера (`studytrack:theme`). При первом посещении используется системная тема. Инициализация выполняется до отображения страницы, чтобы избежать вспышки светлого фона. Тёмная палитра охватывает фон, навигацию, карточки, формы, таблицы, статусы и сообщения. Проверены переключение в обе стороны, сохранение после обновления, формы и мобильная версия.
