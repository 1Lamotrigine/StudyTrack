# SQL Workspace — консоль базы StudyTrack

## Открыть

Запустите приложение обычной командой `npm run dev`, войдите как **admin / admin123** и откройте **http://localhost:3000/dbms**. Ссылка «SQL Workspace» также есть в навигации администратора. В этой консоли используется `getDb()` — та же серверная PGlite и тот же каталог данных, что у учебного портала. Отдельной копии или имитации выполнения SQL нет.

Визуальный референс — классический pgAdmin 4: дерево слева, вкладки и SQL-редактор сверху, результаты и сообщения снизу, меню, панель выполнения и строка статуса. Это собственная реализация для одной базы, а не запущенный Python-сервер pgAdmin.

Официальные референсы:

- [pgAdmin 4 Query Tool](https://www.pgadmin.org/docs/pgadmin4/latest/query_tool.html)
- [Скриншот Query Tool](https://www.pgadmin.org/static/docs/pgadmin4-9.19-docs/_images/query_tool.png)

## Что работает

- CodeMirror SQL Editor: подсветка PostgreSQL, номера строк, автодополнение таблиц и столбцов из каталога, поиск/замена, комментарии, сворачивание, undo/redo.
- До 12 вкладок запросов. Черновики и последние 50 запусков сохраняются в браузере отдельно для каждого администратора. Импорт/экспорт `.sql`, экспорт истории.
- `Ctrl/Cmd+Enter` или F5 исполняет выделение, а если выделения нет — весь скрипт. `Ctrl/Cmd+S` сохраняет файл; `Ctrl+Space` вызывает автодополнение; `Ctrl/Cmd+F` открывает поиск.
- Выполнение настоящих `SELECT`, `INSERT`, `UPDATE`, `DELETE`, DDL, `DO`, функций, процедур, CTE, окон, FTS и JSONB — в пределах возможностей PostgreSQL, встроенного в PGlite.
- Несколько SQL-команд и наборов результатов за запуск. Столбцы сохраняют порядок, даже если имена повторяются. Видны типы PostgreSQL, NULL и количество возвращённых строк.
- Результаты: сортировка, фильтр загруженных строк, страницы по 50/100/250/500, просмотр длинных ячеек, копирование и CSV. На один набор в браузер передаются первые 2 000 строк; общее число возвращённых строк показывается отдельно. CSV содержит загруженные строки, не скрытый полный результат.
- Messages: настоящие command tags, `RAISE NOTICE`, SQLSTATE, DETAIL, HINT и позиция ошибки. Переход к ошибке в редакторе.
- EXPLAIN и EXPLAIN ANALYZE: настоящий план из PostgreSQL в виде раскрывающегося дерева и JSON. ANALYZE действительно выполняет запрос, поэтому интерфейс сообщает об этом перед запуском.
- Дерево пользовательских схем, таблиц, представлений, materialized views, последовательностей, индексов, функций, процедур и триггеров. Объекты и свойства читаются из `pg_catalog`, а не из заранее записанного списка.
- Свойства: столбцы, типы, PK, NOT NULL, значения по умолчанию, IDENTITY, GENERATED, ограничения и индексы. SQL/DDL таблиц собирается из каталога; функции, представления, индексы и триггеры используют `pg_get_*def`.
- Двойной щелчок по таблице открывает «Просмотр данных». В этой вкладке доступны вставка, удаление и изменение обычных ячеек. Для UPDATE/DELETE необходим первичный ключ. PK, IDENTITY и GENERATED изменяются через SQL; вставка явных значений ключей также выполняется через SQL. UPDATE проверяет прежнее значение ячейки, чтобы не затереть параллельное изменение.
- ER-диаграмма строится из действительных FK. Можно открыть структуру таблицы нажатием на её карточку.
- Библиотека из 22 примеров, включая Q01–Q16 исходного проекта. Команды psql удалены, демонстрационные значения `root_id`, `course_id`, `student_id` подставлены с сохранением порядка. Все Q01–Q16 проверены исполнением.
- Обзор базы: имя, пользователь PostgreSQL, версия движка, размер, количество объектов.
- Обе темы, полноэкранный режим, изменяемые размеры дерева и редактора. На телефоне дерево скрыто по умолчанию и открывается кнопкой меню.

## Транзакции

Обычный запуск работает по правилам PostgreSQL и сохраняет изменения. Сценарий транзакции нужно выполнить **целиком в одном запуске**:

```sql
BEGIN;

UPDATE courses
SET description = 'Демонстрация транзакции'
WHERE id = 1
RETURNING id, title, description;

ROLLBACK;
```

Для сохранения замените `ROLLBACK` на `COMMIT`. Если скрипт оставил транзакцию открытой или в состоянии ошибки, консоль откатит её и покажет сообщение. Транзакция не переносится на следующий HTTP-запрос или вкладку.

Кнопка **«С откатом»** сама оборачивает SQL в `BEGIN/ROLLBACK`; явные команды управления транзакцией в этом режиме запрещены. Это удобно для показа UPDATE/INSERT без сохранения данных. Как и в PostgreSQL, последовательности `nextval()` не транзакционны: выданные номера могут пропускаться даже после отката.

Каждый запуск выполняется под `PGlite.runExclusive()`. Запросы приложения ждут освобождения соединения и не попадают внутрь открытой SQL-консолью транзакции. Роль, session authorization и параметры сессии сбрасываются перед и после запуска. Устанавливаются `statement_timeout=15s` и `lock_timeout=3s`; пользователь-администратор может менять параметры самим SQL. Не предусмотрена имитация кнопки отмены, поскольку прерывание синхронной WASM-работы в общем серверном соединении требует отдельной worker-архитектуры.

## Доступ и ограничения

Страница и API доступны только активному администратору. Каждый запрос заново проверяет сессию. POST принимает JSON и проверяет Origin. SQL выполняется с реальными правами владельца встроенной базы, поэтому администратор может читать и изменять все таблицы, в том числе служебные. Выполняйте демонстрационные изменения с откатом или сделайте резервную копию перед показом.

Это одна встроенная PostgreSQL-сессия без TCP-сервера. Подключение к другим базам/серверам, параллельные сеансы, dblink, deadlock между соединениями, интерактивный psql, `COPY STDIN/STDOUT` и расширения, отсутствующие в PGlite, не воспроизводятся. Для выгрузки данных используйте SELECT → CSV. Существующие CLI-скрипты backup/restore описаны в README; импорт бинарного `pg_dump` не реализован.

DDL таблицы — восстановление структуры, а не полный архив с владельцами, комментариями, правами и зависимыми объектами. Триггеры и функции доступны отдельно. PostgreSQL 18 хранит NOT NULL также в `pg_constraint`; при сборке DDL они переносятся в определения столбцов, чтобы не дублировать их неверным синтаксисом.

## Проверки

```sh
npm test
npm run build
npm run format:check
# Для сервера, запущенного на отдельной демонстрационной базе:
TEST_URL=http://127.0.0.1:3110 npm run test:dbms
```

Тесты БД используют независимую PGlite в памяти: SQL с одинаковыми именами столбцов, NULL, DDL/DML, COMMIT/ROLLBACK и автоматический откат незакрытой транзакции, пробный запуск, ошибка и позиция, EXPLAIN, лимит выдачи, метаданные, исполняемость восстановленного DDL, CRUD таблицы с контролем параллельного изменения, функции и Q01–Q16.

HTTP-тест: отсутствие доступа без входа и у студента, доступ администратора, каталог, свойства, настоящий SELECT, временная таблица с DDL/DML внутри откатываемой транзакции, режим отката, SQLSTATE, EXPLAIN и проверка Origin. Рабочие предметные данные не изменяются.

В браузере проверены реальное выполнение SQL, горячая клавиша, ошибка SQLSTATE с позицией, свойства и данные таблицы, открытие формы изменения без сохранения, EXPLAIN и ER-диаграмма.
