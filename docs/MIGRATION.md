# Анализ проекта и перенос

## Исходная архитектура

StudyTrack — учебная система учёта заданий и результатов. Django использует не ORM, а параметризованные SQL-запросы через psycopg. Docker Compose поднимает PostgreSQL и Django. Шаблоны server-rendered, интерфейс на русском, три предметные роли. Подписанная cookie Django идентифицирует пользователя; пароли scrypt.

Девять предметных таблиц: users, course_categories, courses, enrollments, assignments, submission_versions, grades, grade_history, admin_audit_log. Категории образуют дерево, зачисления реализуют M:N. На каждую пару студент–задание допускается несколько версий с уникальным номером, одна оценка на версию. Текущий результат — последняя **оценённая** версия, поэтому неоценённая пересдача не обнуляет отчёт. Отчёт по курсу сначала усредняет результаты каждого студента, затем студентов.

DDL содержит FK, UNIQUE, CHECK, JSONB, generated-столбцы, русский tsvector. Два представления, функция результата студента, процедуры сдачи и оценки, триггеры проверки и истории. Административные процедуры проверяют администратора и пишут аудит. Начальный набор: 13 пользователей, 9 категорий, 6 курсов, 28 зачислений, 12 заданий, 48 версий, 47 оценок. Скрипт объектов демонстрационно исправляет одну оценку и создаёт запись истории.

Учебные материалы охватывают 3НФ, ER-диаграмму, словарь, Q01–Q16, курсоры, FTS/JSONB, EXPLAIN, массовый seed, транзакции, изоляцию, блокировки, deadlock, роли и backup/restore. PDF и HTML — исходные учебные артефакты, их сведения о Django/PostgreSQL относятся к исходной реализации.

## Соответствие маршрутов

Сохранены `/login`, `/`, `/courses`, `/courses/:id`, `/assignments/:id/submit`, `/versions/:id/grade`, `/reports`, `/reports/course/:id`, `/search`, `/admin`, `/admin/users`, `/admin/users/create`, `/admin/users/:id`, `/admin/categories`, `/admin/categories/:id` (0 — создание), `/admin/courses`, `/admin/courses/create`, `/admin/courses/:id`, `/admin/courses/:id/enrollments`, `/admin/assignments`, `/admin/assignments/create`, `/admin/assignments/:id`, `/admin/audit`.

Изменения состояния выполняются Server Actions, а не отдельными Django POST-маршрутами `/role`, `/toggle`, `/reset-password`, `/archive`, `/logout`. Все соответствующие операции доступны формами. Пароль устанавливает администратор; вместо генерации и показа случайного пароля введён явный новый пароль.

## Решения при переносе

- Next.js App Router, TypeScript, React Server Components, Server Actions; сервер Node.js.
- Одна серверная PGlite с файловой персистентностью, singleton переживает HMR. Браузер не получает SQL-клиент и хеши паролей.
- Схема, seed, функции, процедуры, триггеры, представления и индексы сохранены. Инициализация одной транзакцией, таблица версии предотвращает повторный seed. Команды psql и внешние BEGIN/COMMIT удаляются загрузчиком.
- Сессии заменены на криптографически случайные непрозрачные токены; в БД только SHA-256 токена. Cookie HttpOnly, SameSite=Lax. Прежний формат scrypt совместим с Node crypto.
- Роли проверяются на сервере для страниц и мутаций. ID актёра берётся из сессии, не из формы. Server Actions защищают мутации проверкой origin средствами Next.js.
- Дополнительно запрещены циклы категорий любой глубины. В исходнике CHECK запрещал только прямую самоссылку, хотя комментарий админской процедуры обещал защиту от циклов.
- Параметризованные запросы сохранены; raw пароли не пишутся в аудит.
- Интерфейс сохраняет исходную визуальную основу и адаптивность. Сдача остаётся текстовой, как в Django; поле формата описывает ожидаемый результат, загрузки файлов в исходнике не было.

## Ограничения и исходные риски

PGlite сериализует операции одного встроенного соединения; демонстрации двух сессий, deadlock и dblink нельзя честно воспроизвести как PostgreSQL-сервер. Сохранены оригинальные учебные файлы, но они не объявлены рабочими PGlite-тестами. Docker/WSGI/psycopg заменены npm-командами. Не переносится содержимое уже запущенной внешней базы без отдельного экспорта; используются исходные SQL-данные.

Сохранены некоторые особенности исходной модели: каталог виден всем авторизованным пользователям; отчёты видны преподавателям по всем курсам; преподаватель может оценивать только свой курс; архивирование курса не запрещает сдачу автоматически; смена роли может оставить прежние связи курсов/зачислений. Это требует отдельного продуктового решения при дальнейшем развитии.

Учебная реализация не добавляет сброс пароля по email и ограничение попыток входа. Для нескольких серверных реплик нужен полноценный внешний PostgreSQL. Исходные `docs/test_results.md` фиксируют прежние проверки PostgreSQL, не результаты нового приложения. Актуальные проверки находятся в `tests/database.test.ts` и `scripts/smoke.mjs`.

## Проверено в новой версии

`npm test`: создание схемы и seed, три прежних пароля и неверный пароль, сдача и версия №2, отказы повторной сдачи и отсутствия зачисления, чужой преподаватель и балл выше максимума, выставление и исправление оценки с историей, отказ административных действий студенту и отключения себя, создание и изменение пользователя, смена роли, отключение и включение, новый пароль, создание и изменение курса и задания, архивирование, категории и запрет цикла, зачисление и отчисление, аудит, откат транзакции, полнотекстовый поиск, представления, повторная инициализация, файловая персистентность и восстановление архива.

`npm run test:smoke`: реальный HTTP-вход и 33 страницы (5 студент, 7 преподаватель, 21 администратор), запрет админки студенту. TypeScript и production build проходят. В браузере проверено отображение страницы входа. Мобильные сценарии и весь процесс изменения данных через браузер отдельно не автоматизировались.
