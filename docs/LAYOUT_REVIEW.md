# Проверка вёрстки StudyTrack

Дата: 12.11.2026. Проверены общие компоненты и все семейства экранов в `app`, `components`, `features`: вход, обзор по ролям, курсы, задания, сдача, проверка, отчёты, административные формы и SQL Workspace. Дизайн и предметная логика сохранены.

## Найдено и исправлено

| Проблема / допущение | Исправление |
|---|---|
| В административных списках кнопка добавления примыкала к фильтру или таблице без зазора | Добавлен общий контейнер действий с отдельным нижним отступом 16 px |
| Поля фильтров имели `height: 39px`, но наследовали `min-height: 41px`; кнопки оставались 39 px | Общая высота 44 px, одинаковая нижняя линия контролов, исправлена гибкая ширина поискового поля |
| Отступы 17/19/21/22/23/25/27 px складывались непоследовательно, особенно между карточками и формами | Общие переменные бокового поля, ширины контента, отступа секции и карточки; основной интервал 24 px, внутренние интервалы 8/12/16 px |
| На телефоне отчёты и список пользователей расширяли документ до 625 и 393 px при ширине окна 320 px | Удалён абсолютно позиционированный скрытый текст в заголовке таблицы; доступное имя перенесено в `aria-label`, контейнеры таблиц ограничены и позиционированы |
| Таблицы внутри карточек использовали отрицательные отступы и `calc(100% + 20px)` | Убраны расширение и отрицательные поля; таблица остаётся в границах контентной области карточки |
| Высота основного контента зависела от вручную подсчитанной высоты шапки и футера | Flex-компоновка оболочки и контента, футер занимает своё место в потоке без искусственной пустоты снизу |
| После переноса переключателя темы в шапку остались нижние отступы 65/80 px и координаты старой плавающей кнопки | Неиспользуемые компенсационные отступы и координаты удалены |
| Боковое меню не имело управляемой прокрутки на невысоких окнах | Навигация прокручивается внутри доступной высоты; декоративная карточка скрывается при недостатке высоты; блок аккаунта остаётся доступен |
| Мобильные кнопки темы и выхода позиционировались относительно страницы, а не панели | Мобильная боковая панель стала позиционированным контейнером, для бренда зарезервировано место под контролы |
| Шапка предполагала достаточную ширину для подписи, поиска, роли и темы одновременно | Гибкое боковое поле и промежутки, скрытие вспомогательной подписи на промежуточной ширине, ограничение поискового блока |
| Контент карточки задания выбирался по `:nth-child(2)` | Добавлен явный класс `assignment-content`, не зависящий от порядка декоративных элементов |
| Длинные заголовки и подписи могли расширять flex/grid-элементы | Добавлены `min-width: 0`, переносы текста и перенос строки для заголовка со статусом; иконки сохраняют размер |
| Для группы кнопок страницы ошибки использовался класс без CSS | Добавлена компоновка с gap и переносом кнопок |
| Поля мобильных форм использовали маленький шрифт, способный вызвать увеличение страницы при фокусе в iOS | В формах портала на телефоне используется шрифт 16 px, контролы сохраняют высоту не менее 44 px |
| SQL Workspace наследовал от общих форм `width: 100%`, верхний отступ и минимальную высоту для селекторов | Нормализованы поля внутри консоли; селекторы результата и пагинации вернулись к компактным размерам 26/24 px |
| Редактор SQL и минимальная высота вывода могли суммарно превышать доступную высоту; внешний контейнер обрезал низ | Рабочая область допускает прокрутку, редактор адаптируется к короткому окну, для результата сохранена высота, достаточная для данных и контролов |
| Мобильный обозреватель SQL имел жёсткий отступ `top: 72px`, не учитывающий сообщение об ошибке | Обозреватель привязан к рабочей области через `top: 0; bottom: 0` |
| Выпадающее меню последних пунктов SQL-консоли могло уходить за правую границу телефона | Меню привязано к общей полосе меню и ограничено её шириной |
| Полоса вкладок SQL имела меньшую высоту, чем минимальная высота вложенных кнопок | Кнопки соответствуют высоте полосы, вертикальное переполнение отключено; горизонтальная прокрутка сохранена |
| Название движка и текст ошибки SQL могли теснить соседние элементы | Выделены отдельные текстовые контейнеры с управляемым сжатием и переносами |

## Проверка

- 13 экранов администратора на ширинах **320, 768 и 1280 px** — всего 39 сочетаний. После исправлений ширина документа и body не превышает ширину окна.
- Дополнительно проверены мобильные обзор, задания, сдача и результаты студента; обзор, очередь проверки, оценивание и отчёты преподавателя; страница входа.
- В фильтре пользователей измерены одинаковая высота input/select/button **44 px** и одна нижняя линия.
- Мобильное меню SQL Workspace при ширине 320 px занимает область от x=8 до x=312 и не выходит за экран.
- Для SQL-консоли проверено окно **1024×480**: рабочая область прокручивается, строка состояния остаётся в пределах окна; нижняя часть вывода не теряется за обрезанным контейнером.
- Размер селектора пагинации SQL — **24 px** вместо унаследованного размера обычного поля портала.
- Проверены production-сборка, TypeScript и форматирование. HTTP smoke-проверка используется для контроля сохранности маршрутов и входа по ролям.

Широкие таблицы отчётов, SQL, ER-диаграмма и длинные полосы вкладок намеренно имеют **внутреннюю** горизонтальную прокрутку. Она не расширяет всю страницу. Страницы ошибки проверены по исходным компонентам; искусственное падение приложения для визуального теста не вызывалось.
