# Словарь данных StudyTrack

СУБД: PostgreSQL 16. Идентификаторы — `GENERATED BY DEFAULT AS IDENTITY`.
Даты и моменты времени различаются: `date` не используется, все события хранятся
в `timestamptz`; денежные значения в проекте отсутствуют. Дробные измерения
(баллы, проценты) — `numeric`.

Обозначения: **PK** — первичный ключ, **FK** — внешний ключ, **UQ** — UNIQUE,
**GEN** — вычисляемый столбец.

---

## 1. `users` — пользователи

| Столбец | Смысл | Тип | NULL | По умолчанию | Ключи и ограничения |
|---|---|---|---|---|---|
| `id` | Идентификатор пользователя | `integer` | нет | identity | PK |
| `full_name` | ФИО | `text` | нет | — | `length(btrim(...)) >= 2` |
| `email` | Учебный адрес | `text` | нет | — | UQ, `position('@' in email) > 1` |
| `role` | Предметная роль | `text` | нет | — | `CHECK (role IN ('student','teacher','admin'))` |
| `login` | Логин для входа | `text` | нет | — | UQ, `login ~ '^[a-z0-9_.]{3,32}$'` |
| `password_hash` | Хеш пароля (scrypt) | `text` | нет | — | прямой SELECT закрыт правами ролей |
| `is_active` | Учётная запись активна | `boolean` | нет | `true` | — |
| `created_at` | Когда создана запись | `timestamptz` | нет | `now()` | — |

Одна строка — один учебный пользователь. Роль в `users` — предметный атрибут
(`student`/`teacher`/`admin`), отдельный от ролей PostgreSQL (`studytrack_app`,
`report_reader`). Хеш пароля имеет формат
`scrypt$N$r$p$salt_b64$hash_b64` и никогда не хранится в открытом виде.
Операционной роли `studytrack_app` столбец `password_hash` недоступен: SELECT
выдан по столбцам, а чтение хеша возможно только через
SECURITY DEFINER-функцию `fn_login_lookup(text)`.

## 2. `course_categories` — иерархия категорий

| Столбец | Смысл | Тип | NULL | По умолчанию | Ключи и ограничения |
|---|---|---|---|---|---|
| `id` | Идентификатор категории | `integer` | нет | identity | PK |
| `parent_id` | Родительская категория | `integer` | да | `NULL` | FK → `course_categories(id)` `ON DELETE RESTRICT` |
| `title` | Название | `text` | нет | — | `length(btrim(...)) >= 2` |
| `slug` | Латинский код | `text` | нет | — | UQ, `slug ~ '^[a-z0-9-]+$'` |

Дополнительно: `CHECK (parent_id IS NULL OR parent_id <> id)` запрещает
непосредственную самоссылку. Циклы глубже одного узла предотвращаются
рекурсивным запросом Q08 (проверка `NOT child.id = ANY(path_ids)`).
Самостоятельное удаление родителя запрещено, пока у него есть дочерние узлы.

## 3. `courses` — курсы

| Столбец | Смысл | Тип | NULL | По умолчанию | Ключи и ограничения |
|---|---|---|---|---|---|
| `id` | Идентификатор курса | `integer` | нет | identity | PK |
| `category_id` | Категория | `integer` | нет | — | FK → `course_categories(id)` `ON DELETE RESTRICT` |
| `teacher_id` | Преподаватель | `integer` | нет | — | FK → `users(id)` `ON DELETE RESTRICT` |
| `code` | Код курса | `text` | нет | — | UQ |
| `title` | Название | `text` | нет | — | `length(btrim(...)) >= 2` |
| `description` | Описание | `text` | нет | `''` | — |
| `status` | Состояние курса | `text` | нет | `'draft'` | `CHECK IN ('draft','active','archived')` |
| `created_at` | Когда создан | `timestamptz` | нет | `now()` | — |

Удаление категории или преподавателя, на которых ссылаются курсы, запрещено
(`RESTRICT`): история не должна исчезать каскадно.

## 4. `enrollments` — зачисления

| Столбец | Смысл | Тип | NULL | По умолчанию | Ключи и ограничения |
|---|---|---|---|---|---|
| `id` | Идентификатор зачисления | `integer` | нет | identity | PK |
| `course_id` | Курс | `integer` | нет | — | FK → `courses(id)` `ON DELETE RESTRICT` |
| `student_id` | Студент | `integer` | нет | — | FK → `users(id)` `ON DELETE RESTRICT` |
| `status` | Состояние | `text` | нет | `'active'` | `CHECK IN ('active','completed','dropped')` |
| `enrolled_at` | Когда зачислен | `timestamptz` | нет | `now()` | — |

`UNIQUE (course_id, student_id)` — студент зачисляется на курс один раз.
Именно эта таблица разрешает сдачу: процедура `submit_version` проверяет
наличие активного зачисления.

## 5. `assignments` — задания

| Столбец | Смысл | Тип | NULL | По умолчанию | Ключи и ограничения |
|---|---|---|---|---|---|
| `id` | Идентификатор задания | `integer` | нет | identity | PK |
| `course_id` | Курс | `integer` | нет | — | FK → `courses(id)` `ON DELETE RESTRICT` |
| `title` | Название | `text` | нет | — | `length(btrim(...)) >= 3` |
| `description` | Текст задания | `text` | нет | `''` | — |
| `due_at` | Срок сдачи | `timestamptz` | нет | — | — |
| `max_score` | Максимальный балл | `numeric(6,2)` | нет | — | `CHECK (max_score > 0)` |
| `extra` | Доп. параметры | `jsonb` | нет | `'{}'` | `jsonb_typeof = 'object'`; проверки типов ключей |
| `expected_minutes` | Ожидаемое время, мин | `integer` | да | GEN | `GENERATED ALWAYS AS ((extra->>'expected_minutes')::integer) STORED`; `CHECK (NULL OR 5..10080)` |
| `search_vector` | Полнотекстовый вектор | `tsvector` | да | GEN | `GENERATED ... to_tsvector('russian', title || ' ' || description) STORED` |
| `created_at` | Когда создано | `timestamptz` | нет | `now()` | — |

Обязательные ключи `extra`: `submission_format` (text), `expected_minutes` (number),
`allow_revision` (boolean). Проверки `jsonb_typeof` не дают сохранить ключ
неверного типа. Если `expected_minutes` отсутствует, вычисляемый столбец равен
`NULL`; это допустимо. Значение `2` нарушает диапазон; строка `"abc"` даёт
ошибку приведения к `integer`. Индекс GIN строится по `search_vector`,
B-tree — по `expected_minutes`.

## 6. `submission_versions` — версии работ

| Столбец | Смысл | Тип | NULL | По умолчанию | Ключи и ограничения |
|---|---|---|---|---|---|
| `id` | Идентификатор версии | `integer` | нет | identity | PK |
| `assignment_id` | Задание | `integer` | нет | — | FK → `assignments(id)` `ON DELETE RESTRICT` |
| `student_id` | Автор (студент) | `integer` | нет | — | FK → `users(id)` `ON DELETE RESTRICT` |
| `version_no` | Номер версии | `integer` | нет | — | `CHECK (version_no > 0)` |
| `body` | Текст работы | `text` | нет | — | `length(btrim(...)) > 0` |
| `submitted_at` | Время сдачи | `timestamptz` | нет | `now()` | — |
| `is_late` | Сдано после срока | `boolean` | нет | `false` | — |

`UNIQUE (assignment_id, student_id, version_no)` — номер версии уникален внутри
пары «студент — задание». `is_late` вычисляется процедурой `submit_version`
в момент вставки (`now() > due_at`) и хранится как факт.

## 7. `grades` — оценки версий

| Столбец | Смысл | Тип | NULL | По умолчанию | Ключи и ограничения |
|---|---|---|---|---|---|
| `id` | Идентификатор оценки | `integer` | нет | identity | PK |
| `version_id` | Оцениваемая версия | `integer` | нет | — | FK → `submission_versions(id)` `ON DELETE RESTRICT`, UQ |
| `graded_by` | Преподаватель | `integer` | нет | — | FK → `users(id)` `ON DELETE RESTRICT` |
| `score` | Балл | `numeric(6,2)` | нет | — | `CHECK (score >= 0)` |
| `comment` | Комментарий | `text` | да | `NULL` | — |
| `graded_at` | Время выставления | `timestamptz` | нет | `now()` | — |

`UNIQUE (version_id)` — одна актуальная оценка на версию; исправление
обновляет её, а старое значение попадает в `grade_history`.
Правило `score <= assignments.max_score` и «оценивает только преподаватель
курса» проверяются триггером `trg_grades_validate` и процедурой
`grade_version`, потому что затрагивают другие таблицы.

## 8. `grade_history` — история оценок

| Столбец | Смысл | Тип | NULL | По умолчанию | Ключи и ограничения |
|---|---|---|---|---|---|
| `id` | Идентификатор записи | `integer` | нет | identity | PK |
| `grade_id` | Оценка | `integer` | да | — | FK → `grades(id)` `ON DELETE SET NULL` |
| `version_id` | Версия | `integer` | да | — | FK → `submission_versions(id)` `ON DELETE SET NULL` |
| `old_score` | Старый балл | `numeric(6,2)` | да | — | NULL при INSERT |
| `new_score` | Новый балл | `numeric(6,2)` | нет | — | — |
| `action` | Действие | `text` | нет | — | `CHECK IN ('INSERT','UPDATE')` |
| `changed_by` | Кто изменил | `integer` | да | — | FK → `users(id)` `ON DELETE SET NULL` |
| `changed_at` | Когда | `timestamptz` | нет | `now()` | — |
| `comment` | Комментарий оценки | `text` | да | `NULL` | — |

Заполняется триггером `trg_grades_history` после `INSERT`/`UPDATE` в `grades`.
Триггер пишет в другую таблицу, поэтому не возникает бесконечного обновления
той же строки. Записи истории не удаляются каскадно вместе с оценкой.

## Поведение удаления внешних ключей

| Дочерняя таблица | Родитель | Поведение |
|---|---|---|
| `course_categories` | `course_categories` | `RESTRICT` |
| `courses` | `course_categories` | `RESTRICT` |
| `courses` | `users` | `RESTRICT` |
| `enrollments` | `courses`, `users` | `RESTRICT` |
| `assignments` | `courses` | `RESTRICT` |
| `submission_versions` | `assignments`, `users` | `RESTRICT` |
| `grades` | `submission_versions`, `users` | `RESTRICT` |
| `grade_history` | `grades`, `submission_versions`, `users` | `SET NULL` |
| `admin_audit_log` | `users` (актор) | `SET NULL` |

`CASCADE` намеренно не используется: удаление справочника не должно уничтожать
историю. Для удаления курса сначала нужно осознанно удалить/архивировать
связанные данные; в демонстрационном приложении удаление не предусмотрено.

## 9. `admin_audit_log` — журнал административных операций

| Столбец | Смысл | Тип | NULL | По умолчанию | Ключи и ограничения |
|---|---|---|---|---|---|
| `id` | Идентификатор записи | `bigint` | нет | identity | PK |
| `actor_id` | Кто выполнил операцию | `integer` | да | `NULL` | FK → `users(id)` `ON DELETE SET NULL` |
| `action` | Код операции | `text` | нет | — | например `create_user`, `set_role`, `archive_course` |
| `entity` | Тип объекта | `text` | нет | — | `CHECK (entity IN ('user','course','assignment','category','enrollment'))` |
| `entity_id` | Идентификатор объекта | `integer` | да | `NULL` | — |
| `details` | Детали операции | `jsonb` | нет | `'{}'` | произвольный JSON |
| `created_at` | Когда изменено | `timestamptz` | нет | `now()` | — |

Журнал заполняется админскими процедурами (`fn_admin_log`) и только для чтения
со стороны приложения: `studytrack_app` имеет `SELECT`, но не `INSERT`.
Изменения структуры проходят через процедуры `admin_*` из
`db/03b_admin_objects.sql`, которые работают как `SECURITY DEFINER` и проверяют
роль вызывающего функцией `fn_assert_admin`.
